## 2. Primary source — Demystifying Evals for AI Agents

**Publisher:** Anthropic  
**Source:** https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents

### Relevant section: agents are multi-turn systems

Anthropic explains that agents call tools, modify state, and adapt over multiple turns, making them harder to evaluate than single-response systems.

This supports our idea that the final output alone is not enough to understand many failures.

### Relevant section: trajectories / transcripts

Anthropic treats the sequence of model and tool interactions as important evaluation evidence.

This supports:
- retaining enough trajectory information to diagnose behavior;
- inspecting intermediate decisions/tool calls, not only the final answer.

### Relevant section: outcomes

Anthropic distinguishes what an agent *says* it did from the actual external outcome/state.

This supports observability that reaches external systems rather than stopping at model logs.

## 3. Primary source — Multi-Agent Research System

**Publisher:** Anthropic  
**Source:** https://www.anthropic.com/engineering/multi-agent-research-system

### Relevant section: observability and test cases

Anthropic describes watching agents work step-by-step to expose failure modes and says its iteration loop relied on observability and test cases.

This supports:
- inspecting agent trajectories;
- correlating orchestration behavior with failure;
- debugging coordination issues.

### Relevant section: production reliability

The article explains that agents are stateful, errors compound, and durable execution/checkpoints matter.

This supports observability across:
- workers;
- tool calls;
- long-running state;
- retries/recovery.

## 5. Current D3.4 note under review

### Core idea

A production AI request must be **reconstructable across components**.

### What you need to know

Useful telemetry can include:

- request/trace ID;
- model/version;
- prompt/config version;
- retrieval query and document IDs;
- tool names and outcomes;
- dependency latency;
- retries;
- errors;
- token counts;
- cost;
- final outcome;
- escalation/review decision.

For agents, a transcript/trajectory shows the sequence of model and tool interactions.

Do not log secrets or sensitive content indiscriminately.

### Decision rules

- Propagate one trace identity across model, retrieval, tools, queues, and worker agents.
- Log enough to reproduce a failure without turning logs into an uncontrolled copy of sensitive data.
