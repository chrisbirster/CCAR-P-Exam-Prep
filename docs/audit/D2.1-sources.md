# D2.1 Sources — Claude Model Selection

**Objective:** Select appropriate Claude models based on trade-offs  
**Audit status:** HUMAN APPROVED

## 1. Exam subject

The blueprint asks candidates to choose Claude models based on trade-offs.

## 2. Primary source — Model Lifecycle / Deprecations

[Model Lifecycle](../references/model-lifecycle.md)

Anthropic currently documents four lifecycle labels:
- Active;
- Legacy;
- Deprecated;
- Retired.

It also recommends migration/testing before retirement.

## 3. Primary source — Demystifying Evals

[Demystifying Evals](../references/demystifying-evals.md)

Anthropic's eval guidance supports evaluating model/system behavior on the actual workload rather than relying only on generic benchmark reputation.

## 4. Direct evidence vs. interpretation

**Directly supported:**
- lifecycle states;
- model migrations need testing;
- workload-specific evaluation matters.

**Architecture interpretation:**
- choose the least expensive/lowest-latency model that clears a quality threshold;
- route hard cases to a stronger model;
- treat model migration as a production change.

Model names, prices, limits, and current availability are time-sensitive.

## 5. Current note under review

Our note frames model selection as a quality/latency/cost/risk optimization problem and discourages "always strongest" or "always cheapest."
