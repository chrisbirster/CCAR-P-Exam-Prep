## 2. Primary source — Advanced Tool Use

**Publisher:** Anthropic  
**Source:** https://www.anthropic.com/engineering/advanced-tool-use

### Relevant section: tool-definition context bloat

Anthropic gives examples where many MCP/server tool definitions consume a large amount of context before useful work begins.

Short excerpt:

> “Agents should discover and load tools on-demand”

This is direct support for progressive discovery.

### Relevant section: selection accuracy

Anthropic reports that large tool catalogs can produce wrong-tool selection and incorrect-parameter failures, especially for similarly named tools.

This supports the second benefit of progressive discovery:
- not just token savings;
- also reducing irrelevant choices presented to the model.

### Relevant section: Tool Search

Anthropic's Tool Search design keeps a search mechanism and frequently needed tools loaded while deferring long-tail tool definitions until relevant.

This directly supports our pattern:

```text
frequent/critical tools → available immediately
long-tail tools → discover/load on demand
```

### Relevant section: trade-off

Anthropic explicitly says tool search adds a search step, so it is more useful when context savings and accuracy gains justify the latency.

This prevents the false rule:

> Progressive discovery is always better.

For a small tool set used frequently, loading everything may be simpler.

## 3. Primary source — MCP Specification

**Publisher:** Model Context Protocol  
**Source:** https://modelcontextprotocol.io/specification/

MCP defines capabilities and tool/resource exposure, but security authorization remains a separate concern.

This supports our distinction:

> Discovery/visibility is not the same thing as permission.

A tool being absent from immediate context does not itself constitute an authorization boundary.

## 6. Current D3.8 note under review

### Core idea

Do not preload every possible tool or resource when the model needs only a few.

### What you need to know

Large tool catalogs can cause:

- token/context overhead;
- selection confusion between similar tools.

Progressive discovery keeps a small high-value set visible and loads additional tools when needed.

### Decision rules

Immediately expose:
- frequent/critical tools.

Discover on demand:
- long-tail tools;
- specialist tools;
- tools across many independent systems.

Progressive discovery is a context/selection strategy, not an authorization mechanism.

### Common traps

- Loading hundreds of definitions into every request.
- Confusing hidden-from-context with unauthorized.
- Adding discovery complexity to a tiny, frequently used tool set.
