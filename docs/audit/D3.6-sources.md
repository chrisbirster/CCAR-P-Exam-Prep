## 2. Primary source — Contextual Retrieval

**Publisher:** Anthropic  
**Source:** https://www.anthropic.com/engineering/contextual-retrieval

### Relevant section: lexical / BM25 retrieval

Anthropic describes BM25 as useful for exact term matching.

This supports our examples such as:
- identifiers;
- uncommon terminology;
- exact names/error strings.

### Relevant section: semantic retrieval

Anthropic describes embeddings as retrieving by semantic similarity.

This supports:
- paraphrased natural-language queries;
- conceptual similarity when wording differs.

### Relevant section: hybrid retrieval

Anthropic's standard flow combines BM25 and semantic embeddings, then merges results using rank fusion.

This directly supports using hybrid retrieval when both exact terminology and semantic similarity matter.

### Relevant section: reranking

The article evaluates reranking to improve ordering among retrieved candidates.

This supports reranking when first-stage retrieval yields candidates that need a stronger relevance pass.

## 3. Claims that are our architecture interpretation

### Metadata filtering

Filtering by tenant, jurisdiction, date, status, or access policy is common production retrieval design, but the cited Contextual Retrieval article is not the primary source for this claim.

Keep it as architecture guidance unless a dedicated source is added.

### Live API/tool vs. retrieval

Our rule:

```text
stable knowledge → retrieval
current transactional state → authoritative API/tool
```

is a strong systems-architecture heuristic, not a direct statement from the Contextual Retrieval article.

Examples:

```text
employee handbook → retrieval
current PTO balance → HR system API

product manual → retrieval
current inventory → inventory API
```

This distinction is valuable for the exam, but should be labeled **interpretation**.

## 5. Current D3.6 note under review

### Core idea

Different queries need different retrieval signals.

### Keyword retrieval

Strong for exact identifiers, product codes, names, error strings, and uncommon terminology.

### Semantic retrieval

Strong for paraphrases, conceptual similarity, and natural-language questions where wording differs from the source.

### Hybrid retrieval

Combines lexical and semantic signals.

### Metadata filtering

Restricts candidates by properties such as tenant, date, jurisdiction, classification, or document status.

### Live API/tool vs. retrieval

Use retrieval for relatively stable knowledge.

Use a live API/tool for current operational state.

### Decision rule

Choose the retrieval strategy from the query and data characteristics rather than assuming one technique is universally best.
