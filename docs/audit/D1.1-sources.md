# D1.1 Sources — Translate Business Problems into Claude-Based AI Solutions

**Objective:** Translate business problems into Claude-based AI solutions  
**Audit status:** HUMAN APPROVED

## 1. Exam subject

The CCAR-P blueprint asks the architect to translate a business problem into an appropriate Claude-based solution.

Secondary blueprint cross-check: [Secondary Blueprint Cross-Checks](../references/secondary-blueprint-cross-checks.md).

## 2. Primary source — Building Effective AI Agents

[Building Effective AI Agents](../references/building-effective-ai-agents.md)

Anthropic's durable guidance is to start with the simplest workable architecture and add agentic complexity only when it improves results. This supports treating "use an agent" as a design hypothesis rather than a business requirement.

## 3. Primary source — Effective Context Engineering

[Effective Context Engineering](../references/effective-context-engineering.md)

Anthropic distinguishes prompt/context/tool design decisions from the underlying application state and system boundaries. This supports decomposing a business problem into model responsibilities, deterministic responsibilities, context, tools, and state.

## 4. Direct evidence vs. interpretation

**Directly supported:**
- simple/composable approaches are often preferable;
- added agent complexity should earn its cost;
- model/context/tools are architecture choices, not the business outcome.

**Architecture interpretation:**
- our four requirement buckets: outcome, functional, non-functional, risk;
- prompts should not enforce exact authorization or hard numeric policy;
- define success/failure criteria before implementation.

## 5. Current note under review

Our note says:
- begin with the business outcome;
- quantify vague requirements;
- identify hard constraints early;
- decide what Claude owns vs. deterministic software;
- do not automatically build an agent because a stakeholder requests one.
